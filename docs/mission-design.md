# Town Crew 關卡設計原則

更新日期：2026-10-25。

**新關卡在第一次玩法討論時，就要一起規劃固定視角下的場景與動線、四邊取景與主體大小、重玩變化、幼兒可做的選擇，以及同一局如何保存。**
先填完文末的設計清單，再安排模型與實作；首版暫不加入的變化也要寫明理由與後續方向。
模型需求另外對照[建模清單](model-catalog.md)，程式邊界見[架構文件](architecture.md)。

## 熟悉的操作，每局不同的任務

- 保留可辨識的任務目的與因果順序，例如地基完成後才能蓋牆、車輛讓出通道後才能接送。
- 手勢、寬容的操作範圍、自動對準與完成條件保持一致；不要隨機改變拖曳門檻、停留時間或增加額外確認。
- 變化要讓幼兒看得見：不同目的地、房屋外形、車型或住戶。先挑少量有意義的變化，不以組合數量為目標。
- 用場景、物件輪廓、小手與箭頭交代這局要做的事，不依賴閱讀；提示必須對應這局的真實位置。
- 維持固定視角、單指操作、可暫停與重試；隨機性不引入倒數、扣分、突然失敗或不可達目標。
- 完成最後一項工作後，由收工、離場或抵達動畫自然接上慶祝。例如蓋房子在吊車離場後自動歡迎入住，不需要再按門鈴才能過關。

## 整關維持同一視角

- 每關選定單一固定正交視角，從開場、施工、車輛交接到通車與慶祝都保持一致。
  不因階段、車輛或動作中途平移、旋轉、拉近、拉遠、切換鏡頭或跟隨車輛。
- 可見性問題必須用場景配置、物件位置、車輛朝向、工作動線與停靠位置解決。
  規劃時就讓幼兒看得到工具接觸材料、材料被推動／搬起／放下，以及工作的結果；不能用中途換視角補救遮擋。
- 各種左右配置、開發跳階段、重載與 HMR 都沿用該關的固定視角。
  視窗尺寸變化可調整正交投影範圍以容納畫面，但鏡頭位置與朝向保持一致，不由任務進度驅動縮放。
- 在桌面與直向手機畫面檢查完整動作，包含小手提示與實際手指可能遮住的位置；
  不能只確認開場靜止畫面或終點看得見。

## 四邊取景與主體大小

**畫面優先留給車輛、工具、操作物與工作結果；上下左右沒有任務用途的區域應先裁減，讓主體顯示得更大、更容易辨識與抓取。**
固定視角的意思是遊玩途中保持不變，並不代表設計時必須保留原本寬鬆的全景。
本規則同樣適用既有關卡：修改場景、相機、車型、動線或提示時，重新檢查整關必要範圍。
第九關曾裁減左側多餘道路並收緊固定取景，同時縮短手動進出場範圍；這項經驗及九關現況見[取景檢視紀錄](mission-framing-audit.md)。

### 先定義整關必要範圍

- 在模型與場地定案前，列出所有階段、合法配置與選擇順序會用到的範圍，再投影到螢幕上檢查四邊。
  包含整台車、轉彎時的車頭／車尾、支撐腳、挖臂、抬起的車斗、吊鉤與貨物、升桶、開門、上下車與成果演出；不能只取物件中心或停妥姿勢。
- 分清楚「全程不使用的背景」與「稍後才使用的空間」。等候車格、另一個可選目標、第二趟換位、後退及工具最高點，當下空著也不代表能裁。
- 手動操作的抓取區、真實目標、完整拖曳路徑與小手提示要留在可用畫面內，並避開頂部控制列、底部進度與手指遮擋。
  自動進出場可以跨越畫面邊緣；到達可操作位置時須看清主體，離場則須整車離開後才交接，不能要求孩子追到畫面外繼續拖。
- 景觀可超出畫面，不為了保留整棵樹、整排背景房屋、完整山頭或遠處水面而縮小工作車。
  同時保留足以辨認道路、碼頭、山路與服務對象的情境，不以填滿畫面為目的。

### 逐邊取捨，再調整固定投影

每關提案與場景驗收都記錄下表；四邊分別填寫，不能只寫「畫面置中」或「手機可見」。

| 螢幕邊緣 | 現有／預留內容 | 全流程必須保留的理由 | 可裁部分與採用方式 | 最不利配置、階段與驗證結果 |
| --- | --- | --- | --- | --- |
| 上 | 待填 | 待填 | 待填；不裁也須說明 | 待填 |
| 下 | 待填 | 待填 | 待填；不裁也須說明 | 待填 |
| 左 | 待填 | 待填 | 待填；不裁也須說明 | 待填 |
| 右 | 待填 | 待填 | 待填；不裁也須說明 | 待填 |

- 先減少純背景與多餘的進出場直線，再選擇能包住必要範圍的固定投影大小與中心；容許不對稱取景，不要求左右各留一樣多的空地。
  新取景仍須讓所有配置共用同一相機位置、朝向及取景規則，不隨階段或本局配置追焦。
- 「裁減」是重新設定固定取景與必要的場地配置，不是用 CSS 遮住畫面。遮住空白、只把主體移到中央，或只減少背景模型，都不會自動放大車輛。
- 桌面與直向手機分別判斷限制來源。現有正交相機以最小高度與最小寬度共同容納場景：
  直向手機通常受左右範圍限制，僅降低最小高度不會放大車輛；橫向畫面則可能受高度限制。
  想增加主體大小，要縮小真正限制比例的範圍；若那裡已有必要動線，先評估緊湊配置或較早自動接手，再決定是否維持原取景。
- 相機收緊時同步核對手動行程、自動接手點、完整離場距離、地面覆蓋及近裁切面，還有投影後的命中區與提示。
  不把裁切造成的操作問題用更大的隱形命中框掩蓋，也不為了放大而犧牲整車淨空或改成中途縮放。

### 取景驗收

- 用相同畫布尺寸、配置與階段比較修改前後，記錄代表車輛及主打工具的螢幕大小、四邊保留理由與實際改善；不要求所有關卡達到同一放大比例。
- 至少檢查桌面、直向手機與產品支援的窄／矮畫面；記錄實際 canvas 尺寸，開發面板不能被誤算成遊戲寬高。
  必須包含左右／路線配置、最高／最遠工具姿態、車門與乘客、手動起終點、交接與完成畫面；一張停車截圖不能代替全流程。
- 依[驗證指南](effect-verification.md#按變更選擇驗證)選擇相關 domain／投影檢查，並在內建瀏覽器操作受影響流程，包含取消、部分工作續玩與離場。
  區分「裁切候選」「程式已修改」「完整操作已驗證」；尚未驗證的邊界不得標成安全裁切值。

## 分清楚系統變化與幼兒選擇

| 類型 | 可以改變什麼 | 設計方式 |
| --- | --- | --- |
| 場地與路線 | 左右工地、進場方向、救援對象的位置 | 從已驗證的完整配置中選取，連同路線、停靠位置和提示一起變化。 |
| 物件與成果 | 房屋外形、合適的車型、牆面或車身配色 | 保留物件的用途與辨識特徵；造型變化仍須能完成相同任務。 |
| 角色與情境 | 入住家庭、寵物、等待協助的角色 | 每局維持清楚的任務對象與適當長度；避免因抽選增加工作量。 |
| 幼兒自主選擇 | 澆灌順序、先救誰、先派哪台重機 | 這些是玩家決定，不由隨機結果覆蓋；可選順序仍須符合任務的先後依賴。 |

外觀變化與操作位置的變化可以分批實作。顏色不能成為唯一的任務辨識方式；
即使換色，仍要能靠造型、位置、圖示或輪廓知道該操作誰、放到哪裡。

## 新局、重載與不重複規則

| 時機 | 預期行為 |
| --- | --- |
| 從選關進入、按重新開始或再玩一次 | 清除本關工作進度，產生新一局配置；完成標記與音效偏好保留。 |
| 同一關重新整理、開發 HMR | 還原同一局的配置、配色、幼兒選擇與已完成工作，不重新抽選。依既有規則解除失效的拖曳操作。 |
| 開發模式跳階段或重設階段 | 保留目前配置，方便反覆檢查同一種情況；另提供明確的配置選擇或重抽入口。 |
| 首次遊玩或沒有可用的上一局記錄 | 從合法配置選取，不能因儲存不可用而卡住遊戲。 |

每關明確指定「主要變化」，例如警察的路線配置、蓋房子的屋型。
只要有其他合法選項，新局就避免和上一局相同；不要只靠機率期待它剛好不同。
若主要配置只有一種，記錄此限制；次要裝飾不必每項都保證不同。
需要避免對調也視為重複的項目，像交通救援的兩台車配色，須另外寫清楚比較方式。

本局配置與上一局摘要分開保存：清除工作進度時，仍能用上一局摘要選出不同的新局。
配置一次決定並存入關卡狀態；畫面、碰撞／命中判定、路線與提示共同讀取它。
逐幀更新、重新渲染或重建模型時不重新抽選會影響遊戲的內容。
新增配置欄位時同步處理存檔版本、必要欄位與合法值檢查；只接受完整目前版本，舊格式開新局，不增加遷移分支。目前格式的重載保留已完成工作及玩家選擇。

## 每種配置都要能順利完成

- 先定義少量完整、合理的配置，再在配置內搭配外觀；不要獨立亂抽每台車的位置與方向，造成動線互相衝突。
- 換邊或換車型時，一起檢查整個車身、轉彎範圍、支撐腳、吊物、乘客上下車與前後車交接。
  車身不能穿過房屋、路障或其它車輛；接送門、抓取點和目標不能被遮住。
- 大目標、實際安裝位置、自動對準區域、小手示範、文字方向與停車輪廓要來自同一套配置。
- 工作數量若有變動，同步檢查完成判定、進度計算、車輛圖示與進度條排版。
- 開發時能指定配置，測試時能固定抽選結果；純邏輯涵蓋所有主要配置及允許的操作順序。
  瀏覽器檢查不同配置的實際幾何與提示，並用滑鼠、觸控跑相關流程。
- 驗證連續重玩不重複、同局重載不重抽、中途取消不丟失已完成工作、目前格式可接續、舊格式開新局。
  不用大量隨機重跑取代指定配置的可重現檢查。

配置與抽選規則先留在各關的純 TypeScript domain，場景依配置顯示。
沿用目前可注入抽選函式、直接指定配置的做法即可；不為隨機性另建通用關卡引擎。

## 修馬路重玩變化（已實作）

維持三次挖取裝車、一次清運、一次填料與兩趟壓路。三塊剩餘路面都能選，提示優先引導最近的一塊；完成一塊後仍由幼兒決定下一塊。

- **破損配置**：前後錯落、並排裂開、集中破損。每種有固定且可達的位置、路面塊比例與旋轉角度；坑洞、填料和最後修補面採同一輪廓。
- **左右工地**：整套車輛、路障、進出場、拖曳座標及提示一起換邊；不改手勢門檻、挖掘數量或壓路趟數。
- **新局／續玩**：選關進入或重新開始會避開上局破損配置並換邊；重新整理與 HMR 保留配置、已裝車順序、手持碎塊及各階段進度。缺少目前必要欄位或版本不符的存檔開新局。
- **開發驗證**：`pattern=staggered|split|clustered`、`layout=0|1` 可指定配置；開發面板同步提供選項。切換／重設階段保留配置，三種破損 × 兩側 × 六種順序可重現測試。

## 蓋房子重玩變化（已實作）

維持兩層樓、四種工程車、兩次送貨與六次吊裝，保留基底、澆灌、兩層組裝的因果順序。

| 項目 | 實作 | 規則 |
| --- | --- | --- |
| 屋型 | 尖屋頂、單斜屋頂、平屋頂，搭配門窗比例與窗格變化 | 新局避開上一個屋型；三種屋頂依實際高度建立吊裝目標，抬升後才移至完成結構上方。 |
| 配色 | 四組牆面／門窗配色，搭配三種屋頂色 | 新局避開上一組配色；左上小圖呈現本局屋型與配色，不需要點擊確認。 |
| 入住角色 | 三種成人／孩子組合，以及無寵物、小貓或小狗 | 工程車離場後，開車停進車庫、下車走到門口再慶祝；沿用住戶、共用小客車及寵物。 |
| 工地 | 房子、材料區、車輛進出與吊車位置整套左右換邊 | 新局換邊；固定相機，目標、命中判定、小手與文字方向使用同一套配置。 |
| 澆灌 | 任選三區的先後順序，也可中途換區再回來 | 保留每區部分澆灌量，三區全滿才進入送貨；所有未完成區域同時顯示光圈。 |

屋頂選色原本規劃保留給幼兒，但實際試玩會卡在此介面，因此取消選色與「吊屋頂囉」確認。
二樓牆面裝好後，沿用拖空鉤取貨、自動掛起、拖吊鉤或貨物安裝的流程取本局配色屋頂；完工也不需要按門鈴。
這次經驗作為後續設計原則：**裝飾選項若阻擋幼兒繼續核心操作，優先自動搭配；不為了增加選擇而增加必要步驟。**
有意義的選擇可直接融入操作，例如先澆哪區，而不另開確認介面。

旁邊的敞開式單車庫只在車輛交接空檔形成，不增加四種工程車、兩批送貨及六次吊裝的工作量：
砂石車離場後補車庫地基；水泥車離場後鋪車庫地板、車道與步道；第一批平板車離場後立車庫牆面
（吊車仍停在後方等待）；最後吊車完全離場後補車庫屋頂。每段約 0.7 秒，完成後才讓下一台車或家庭車進場。
**附屬建物與環境變化安排在操作完成、工作車離場後的交接空檔，不與幼兒操作或車輛進出動畫同時發生。**
車庫與主屋配色相同；吊車使用後方通道，家庭小客車使用前方車道轉彎停車，家人從車側下車、
繞過車尾並沿步道走到門口。約十秒的入住動畫全自動，車停妥才開門，所有家人抵達才亮燈慶祝。
完整的車庫、行車路線、車門及步道都跟工地一起鏡射；開放入口讓幼兒看得見停好的車。

版本 6 存檔保存空鉤／掛貨狀態、吊鉤位置、本局配置、屋頂顏色、施工、交接空檔與入住進度。
完整目前格式在重載與 HMR 後接續；已完成的房屋直接顯示停好車與門口家庭，不重新播放入住。
版本 1～5 或缺少必要欄位時開新局。

## 碼頭搬貨重玩變化（已實作）

每局四種運具、兩箱物資、兩次吊裝、兩趟叉運，重玩切換運貨方向：

- 卸船進城：貨船靠岸 → 空車到位 → 吊卸到碼頭 → 吊車離場 → 叉貨裝車 → 堆高機離場 → 卡車送貨 → 空船離港 → 六秒城鎮收貨與慶祝。
- 裝船出發：空船靠岸 → 載貨車到位 → 叉貨卸車到碼頭 → 堆高機與空車離場 → 吊車展開 → 吊裝上船 → 吊車離場 → 幼兒拖貨船出發 → 對岸小鎮收貨與慶祝。

送貨車／船到出口後自動完成離場；船與工作車依畫面寬度駛出，完整離開畫面後才接下一段。

- **主要配置**：左右兩套完整鏡射碼頭，船與卡車從相反側到位，碼頭、吊車支撐腳、棧板、叉運與出口整套協調。新局有上一局記錄時保證切換運貨方向，左右配置獨立抽選，形成四種組合。
- **外觀**：四組船身配色，新局換色；食物／玩具圖樣與棧板結構保持辨識，不以顏色判定正確目的地。
- **場景與落點提示**：房屋與樹木放在水岸兩端的陸地，前方卡車通道保持可見。船形虛線泊位只在靠岸時顯示，到位淡出；船上或岸上卸放時只顯示下一個落點的半透明棧板貨箱，放妥淡出，不保留常駐空框。水面短波紋緩慢漂移、淡入淡出，行船帶短尾波。
- **幼兒選擇**：卸船局拖空鉤到任一船上貨箱，自動掛起後拖吊鉤或貨箱卸放，再拖堆高機向任一岸上棧板；裝船局先拖堆高機向任一車上貨箱，再拖空鉤取任一岸上貨箱，拖吊鉤或貨箱到船上。卸貨與裝貨順序獨立。沒有選色或必要確認畫面。
- **叉貨演出**：第一趟從外側接近，先沿弧線轉彎再橫向進叉；固定鏡頭的左右配置都能看清側面插叉與抬起。第一箱裝車後回到兩貨位間，第二趟從空出的第一個貨位進叉，依裝車順序調整方向。兩趟載貨都直接沿前進弧線轉向陸側，不先倒退重走進叉路線；貨箱、車身與貨叉避開另一箱。貨箱卸放時轉向對準貨叉，四面圖樣可辨識，動線保留等候人員的空間。
- **叉貨卸車**：裝船局先將貨叉抬到車斗高度再插入，抬起貨箱、退出車側，再降叉並轉向碼頭。低位搬到岸上，向前放下後退出；兩趟完成後讓出吊車工作區。
- **續玩**：版本 3 保存空鉤／掛貨狀態、吊鉤位置、方向、船色、配置、兩種順序、懸吊位置、部分行駛、堆高機選箱與載貨、自動交接及收貨計時；版本 1／2 開新局，完整目前格式保留已懸吊貨物。重載清除無效手指與未完成停留；完成存檔不重播收貨。
- **開發與驗證**：`mission=port-cargo`、`direction=unload|load`、`layout=0|1`、`palette=0..3` 與各方向階段能指定重現。規則檢查兩方向 × 兩配置 × 兩卸貨順序 × 兩裝貨順序，以及船車中斷、取消停留、有效提早放手、叉運與自動裝車重載、整台堆高機與卡車間的空間。瀏覽器用滑鼠與直向手機觸控走完整流程，開發檢查保留叉上與懸吊貨物跨 reload／HMR，並驗證切換方向與跳階段。
- **首版暫緩**：貨櫃堆疊、多目的地與額外中轉搬運，先保留四種運具各自不同的作用；真實幼兒試玩再判斷長度與選箱操作。

## 山路搶通重玩變化（已實作）

- **固定任務**：兩次推土 → 三塊大石頭裝車 → 鏟裝機兩趟散土裝車 → 清運車離場 → 一次清掃 → 工作車離場 → 自動通車慶祝。幼兒幫等候的小車重新通行，首版不追加補路或壓路。
- **主要變化**：兩種落石分布 `spread`／`cluster`，新局保證換分布；左右完整施工配置獨立抽選，兩種分布 × 兩側共四套。每套的裝車區、推土車道、清掃路線、抓取與目標光圈一起鏡射。
- **幼兒選擇**：兩堆散土的兩種順序、三塊大石頭的六種裝車順序由孩子獨立決定。拖到土堆後停留或有效放手才決定進鏟，連續拖曳掠過較近土堆不提前鎖定，沒有顏色測驗或必要確認。
- **模型與動線**：沿用原天然大石頭、原挖土機、原綠色清運車、原清掃車及街景人物／道具，新增推土機與山景。整關固定視角，推土機沿兩條橫向車道把土堆推到裝車區旁，從側面露出車身、刮板與移動中的土石；抬板退到土堆後方才換道。前側道路與護欄留出倒退／換道空間。小型四輪鏟裝機從兩堆外側，以側面露出低位鏟入，收斗退開後直接穿過已清出的地面到車尾停妥，停車與抬升分成兩次操作，抬到頂才自動前進與翻斗落料，退開車斗才降鏟。第一趟倒完停在剩餘土堆旁，第二趟倒完從車尾離場。細砂土殘留及已移走的土堆位置可通行，僅避讓仍在場的土堆、大石、車輛及護欄／路障。砂石車沿用原車斗與底盤長度，先放兩塊底石、第三塊搭在中間，再倒入砂土填空隙，不用砂土墊高石頭。散土隨鏟入減少、鏟斗出現載料，倒料時車斗同步增加；鏡頭保持固定，兩側配置都露出工具與土料。大石頭往山側退讓、交通錐與裝車區留出通道，挖土機先裝大石、完全離場後才讓鏟裝機進場，所有工程車完全離場後才撤路障。
- **鏟裝操作**：每趟為「拖到土堆鏟起 → 拖到車尾停好 → 另一次向上拖曳抬升」。停車後等待新手勢，持續按住不自動接上抬升；部分抬升可放手、取消、重載續玩。抬到頂後自動完成前進與翻斗，不要求幼兒同時轉向、升臂及倒料。
- **續玩**：版本 3 保存作業順序、配置、鏟裝選堆／部分行駛／滿鏟／停妥／部分抬升／落料時鐘、散土與大石順序及清運／清掃進度；完整版本 3 保留明確作業順序與進度；版本 1／2 開新局，新局／重玩採先石後土。重載與 HMR 解除手指與未提交停留，保留已完成工作。新局摘要與進度分開；完成存檔不重播通車。
- **開發驗證**：`mission=mountain-clearance`、`pattern=spread|cluster`、`layout=0|1` 與各階段可指定。規則涵蓋四配置 × 兩種鏟土順序 × 六種大石順序與真實模型淨空；瀏覽器用滑鼠與直向手機觸控檢查各配置、鏟入／倒料可見性、取消、部分行駛／滿鏟／倒料／載石重載、持續按住隔離、徽章與重玩。開發檢查 HMR 與指定階段保留配置。
- **待試玩**：確認推土方向、第二趟換位、鏟土與落料、大石頭裝入真實車斗的辨識，以及五種車輛的整關長度。

## 乘客轉運站重玩變化（首版）

- **固定任務**：公車載六人抵達、開門下車、離站 → 計程車與本局隨機選出的校車或遊覽車各接兩人 → 另一台大型車最後接人 → 自動揮手慶祝。遊覽車無論先後，皆先裝一只行李再讓兩位旅客上車；乘客沿實際月台／門洞走動，不要求閱讀或拖人配對。
- **固定視角**：同一正交全景露出乘客側。道路改為寬 5 公尺、左進右出的單向通行，以箭頭標示，不畫中央分隔線；前側為計程車專用及大型車共用停靠彎，後側為校車、遊覽車獨立路邊等候格，停車不佔通行空間。
- **畫面取捨**：移除大迴轉，四車都沿同向前進曲線進出；同一緊湊視角涵蓋等候車格、兩個停靠彎與連續候車月台。候車亭只覆蓋右端長椅，學童的選擇標籤放在等候車上方，避免遮住車身。
- **離站與行人動線**：計程車及大型車由停靠彎斜向匯出，再沿主路往右離站；共享路徑和鋪面輪廓檢查整車與分隔植栽、候車區、站房及等候車的淨空。乘客全程沿連續月台行走，到車門才跨上車。
- **主要變化**：月台／靠站區在左或右，共兩套完整配置。新局保證換配置與客車配色，並獨立隨機決定校車或遊覽車與計程車同行；學童保留背包、計程車保留頂燈、校車保留長車頭與黃色，避免只靠顏色辨識。三種乘客服裝組合獨立抽選。
- **幼兒選擇**：計程車與本局同行車先從畫面外開進等候位，再同時顯示光圈、車旁圖示與兩車進度圖示；接送順序由孩子直接拖車決定，圖示按鈕只換小手提示。先派車完整離站才開放下一台，第三台最後到站。每局工作數量一致。
- **大型車交接與行李**：前兩台接送車完整離站後，另一台大型車從畫面外駛入等候點；動畫停妥後才開放拖車。遊覽車先接人時，裝行李後回到前段接送流程；最後由校車接學童，不重做行李。裝入的行李以車內固定位置及車身角度呈現，轉彎或重載不會偏離行李艙。
- **中斷與續玩**：版本 4 保存本局同行車、配置、接送順序、選定車輛、部分行駛與開門、行李位置及自動進場、上下車與離場時鐘；版本 1／2／3 或缺少同行車時開新局。鬆手／取消保留已做的動作；重載與 HMR 清掉舊手指及未提交行李停留，完成局不重播出發。新局摘要與進度分開保存。
- **沿用與新增**：計程車沿用可開門小客車；住戶原樣抽成共用人物；站務員、房屋、樹與長椅沿用既有模型。新增三種大型客車的可辨識車體、實際乘客門與行李艙、行李箱及低矮站場配件，記錄於建模清單。
- **驗證**：可指定 `mission=passenger-transfer&stage=…&layout=0|1&palette=0..3&companion=school|coach`；純規則涵蓋兩配置 × 兩同行組合 × 兩接送順序、各階段續玩、未完成手勢、自動交接、不重複配置、整車淨空與行李箱全幾何艙內固定。以內建瀏覽器檢查桌面與直向手機的選車、靠站、開門、行李、最後一台接人及重載。
- **暫緩與試玩**：首版維持四車、六人與一只行李，不追加第五種車、收費、分類測驗與額外目的地。實際幼兒試玩再確認車門手勢、接送順序理解與長度。

## 垃圾車清潔隊重玩變化（第九關）

- **固定工作量**：垃圾車收兩袋及一次升桶 → 回收／廚餘車依本局抽選先後各完成兩件搬運／一次側升桶 → 原清掃車一次清掃 → 完整離場才慶祝。
- **道路與固定視角**：主道路中心線由兩側邊界計算；近側收運停車彎使用不同鋪面、斜向靠入／匯出，整車停妥後不佔道路。兩套配置都保留同一固定視角、車尾及近側作業可見性。
- **系統變化**：紙箱／空瓶／鋁罐／報紙四選二，共六組；新局避免同一無序組合，並換配置／車色。回收先到或廚餘先到獨立隨機，允許重複；整局只抽一次。
- **幼兒選擇**：兩袋垃圾及當局兩件回收物各自由選擇裝車順序；未抽中的物品不顯示，沒有分類測驗或選色確認。
- **續玩**：版本 2 保留內容、車序、實物位置／裝車順序、空桶、部分工作與自動動畫。舊版／缺欄位開新局，徽章保留；重新整理及 HMR 不重新抽選。
- **模型與淨空**：原清掃車、平板車、底盤、人物及街景沿用；新增鋁罐籃與報紙束。廚餘側架行車收折，回收物以車內座標隨車轉彎，空桶回人行道避讓刷具。
- **驗證**：`mission=sanitation&stage=…&layout=0|1&service=recycle-first|food-first&cargo=0..5`；規則涵蓋 96 種完整工作組合、所有入口／續玩、中心線、整車鋪面／對向車道淨空、實物車斗接觸及桌面／手機可見性；瀏覽器跟隨實際提示操作。
- **暫緩**：多站巡迴及處理場卸貨，先由幼兒試玩目前四車、兩種倒桶與兩件回收物。

## 每個新關卡提案必填

- [ ] **任務與固定流程**：幼兒要幫誰、完成什麼；哪些階段有先後依賴，最後如何自動接上慶祝？
- [ ] **固定視角與可見性**：是否從開場到完成都保持同一視角？如何用配置、朝向與動線讓工具、材料移動及工作結果在桌面／手機都看得見？
- [ ] **四邊取景與主體大小**：填寫[四邊取捨表](#逐邊取捨再調整固定投影)，逐一說明上／下／左／右可裁與必留內容；桌面與手機各受哪個範圍限制？預計如何讓車輛及主打操作足夠大，並保留全部配置、極限姿態、提示與進出場？
- [ ] **本局變化**：主要變化是什麼，有幾套合法配置；哪些屬外觀、哪些會改變操作位置？首版未納入的項目與理由是什麼？
- [ ] **幼兒選擇**：哪些顏色、對象或工作順序由孩子決定？哪些不能被隨機覆蓋？
- [ ] **重玩與存檔**：如何避開上一局；目前格式在重新整理、HMR、重設階段各保留什麼？舊格式與缺少必要欄位時是否安全開新局？
- [ ] **場景與模型**：列出動線、停靠位置、真實目標、提示與需要沿用／新增的模型；每套配置是否都看得見、碰得到、走得通？
- [ ] **驗證方式**：如何指定每套配置重現問題；檢查哪些操作順序、重載情況、滑鼠與觸控流程？依[取景驗收](#取景驗收)記錄畫布尺寸、前後主體大小、最不利階段與四邊檢查結果。

關卡完成後，把已實作項目、暫緩項目與幼兒試玩發現同步寫回計畫，讓文件反映實際能力。
