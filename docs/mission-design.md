# Town Crew 關卡設計原則

更新日期：2026-09-26。

**新關卡在第一次玩法討論時，就要一起規劃重玩變化、幼兒可做的選擇，以及同一局如何保存。**
先填完文末的設計清單，再安排模型與實作；首版暫不加入的變化也要寫明理由與後續方向。
模型需求另外對照[建模清單](model-catalog.md)，程式邊界見[架構文件](architecture.md)。

## 熟悉的操作，每局不同的任務

- 保留可辨識的任務目的與因果順序，例如地基完成後才能蓋牆、車輛讓出通道後才能接送。
- 手勢、寬容的操作範圍、自動對準與完成條件保持一致；不要隨機改變拖曳門檻、停留時間或增加額外確認。
- 變化要讓幼兒看得見：不同目的地、房屋外形、車型或住戶。先挑少量有意義的變化，不以組合數量為目標。
- 用場景、物件輪廓、小手與箭頭交代這局要做的事，不依賴閱讀；提示必須對應這局的真實位置。
- 維持固定視角、單指操作、可暫停與重試；隨機性不引入倒數、扣分、突然失敗或不可達目標。
- 完成最後一項工作後，由收工、離場或抵達動畫自然接上慶祝。例如蓋房子在吊車離場後自動歡迎入住，不需要再按門鈴才能過關。

## 分清楚系統變化與幼兒選擇

| 類型 | 可以改變什麼 | 設計方式 |
| --- | --- | --- |
| 場地與路線 | 左右工地、進場方向、救援對象的位置 | 從已驗證的完整配置中選取，連同路線、停靠位置和提示一起變化。 |
| 物件與成果 | 房屋外形、合適的車型、牆面或車身配色 | 保留物件的用途與辨識特徵；造型變化仍須能完成相同任務。 |
| 角色與情境 | 入住家庭、寵物、等待協助的角色 | 每局維持清楚的任務對象與適當長度；避免因抽選增加工作量。 |
| 幼兒自主選擇 | 澆灌順序、先救誰、先派哪台重機 | 這些是玩家決定，不由隨機結果覆蓋；可選順序仍須符合任務的先後依賴。 |

外觀變化與操作位置的變化可以分批實作。顏色不能成為唯一的任務辨識方式；
即使換色，仍要能靠造型、位置、圖示或輪廓知道該操作誰、放到哪裡。

## 新局、重載與不重複規則

| 時機 | 預期行為 |
| --- | --- |
| 從選關進入、按重新開始或再玩一次 | 清除本關工作進度，產生新一局配置；完成標記與音效偏好保留。 |
| 同一關重新整理、開發 HMR | 還原同一局的配置、配色、幼兒選擇與已完成工作，不重新抽選。依既有規則解除失效的拖曳操作。 |
| 開發模式跳階段或重設階段 | 保留目前配置，方便反覆檢查同一種情況；另提供明確的配置選擇或重抽入口。 |
| 首次遊玩或沒有可用的上一局記錄 | 從合法配置選取，不能因儲存不可用而卡住遊戲。 |

每關明確指定「主要變化」，例如警察的路線配置、蓋房子的屋型。
只要有其他合法選項，新局就避免和上一局相同；不要只靠機率期待它剛好不同。
若主要配置只有一種，記錄此限制；次要裝飾不必每項都保證不同。
需要避免對調也視為重複的項目，像交通救援的兩台車配色，須另外寫清楚比較方式。

本局配置與上一局摘要分開保存：清除工作進度時，仍能用上一局摘要選出不同的新局。
配置一次決定並存入關卡狀態；畫面、碰撞／命中判定、路線與提示共同讀取它。
逐幀更新、重新渲染或重建模型時不重新抽選會影響遊戲的內容。
新增配置欄位時同步處理存檔版本、合法值檢查與舊存檔遷移，保留已完成的工作及玩家選擇。

## 每種配置都要能順利完成

- 先定義少量完整、合理的配置，再在配置內搭配外觀；不要獨立亂抽每台車的位置與方向，造成動線互相衝突。
- 換邊或換車型時，一起檢查整個車身、轉彎範圍、支撐腳、吊物、乘客上下車與前後車交接。
  車身不能穿過房屋、路障或其它車輛；接送門、抓取點和目標不能被遮住。
- 大目標、實際安裝位置、自動對準區域、小手示範、文字方向與停車輪廓要來自同一套配置。
- 工作數量若有變動，同步檢查完成判定、進度計算、車輛圖示與進度條排版。
- 開發時能指定配置，測試時能固定抽選結果；純邏輯涵蓋所有主要配置及允許的操作順序。
  瀏覽器檢查不同配置的實際幾何與提示，並用滑鼠、觸控跑相關流程。
- 驗證連續重玩不重複、同局重載不重抽、中途取消不丟失已完成工作、舊存檔可接續。
  不用大量隨機重跑取代指定配置的可重現檢查。

配置與抽選規則先留在各關的純 TypeScript domain，場景依配置顯示。
沿用目前可注入抽選函式、直接指定配置的做法即可；不為隨機性另建通用關卡引擎。

## 蓋房子重玩變化（已實作）

維持兩層樓、四種工程車、兩次送貨與六次吊裝，保留基底、澆灌、兩層組裝的因果順序。

| 項目 | 實作 | 規則 |
| --- | --- | --- |
| 屋型 | 尖屋頂、單斜屋頂、平屋頂，搭配門窗比例與窗格變化 | 新局避開上一個屋型；三種屋頂依實際高度建立吊裝目標，抬升後才移至完成結構上方。 |
| 配色 | 四組牆面／門窗配色，搭配三種屋頂色 | 新局避開上一組配色；左上小圖呈現本局屋型與配色，不需要點擊確認。 |
| 入住角色 | 三種成人／孩子組合，以及無寵物、小貓或小狗 | 完工後自動迎接；沿用原住戶與消防小貓，新增共用小狗。 |
| 工地 | 房子、材料區、車輛進出與吊車位置整套左右換邊 | 新局換邊；固定相機，目標、命中判定、小手與文字方向使用同一套配置。 |
| 澆灌 | 任選三區的先後順序，也可中途換區再回來 | 保留每區部分澆灌量，三區全滿才進入送貨；所有未完成區域同時顯示光圈。 |

屋頂選色原本規劃保留給幼兒，但實際試玩會卡在此介面，因此取消選色與「吊屋頂囉」確認。
二樓牆面裝好後，吊車自動吊起本局配色的屋頂，孩子直接接著安裝；完工也不需要按門鈴。
這次經驗作為後續設計原則：**裝飾選項若阻擋幼兒繼續核心操作，優先自動搭配；不為了增加選擇而增加必要步驟。**
有意義的選擇可直接融入操作，例如先澆哪區，而不另開確認介面。

版本 3 存檔保存本局配置、屋頂顏色與施工進度；版本 1／2 保留原尖屋頂、原工地、原家庭及既有顏色。
停在舊選色階段的存檔自動接上吊裝，已完成的舊房屋不被重抽。

## 每個新關卡提案必填

- [ ] **任務與固定流程**：幼兒要幫誰、完成什麼；哪些階段有先後依賴，最後如何自動接上慶祝？
- [ ] **本局變化**：主要變化是什麼，有幾套合法配置；哪些屬外觀、哪些會改變操作位置？首版未納入的項目與理由是什麼？
- [ ] **幼兒選擇**：哪些顏色、對象或工作順序由孩子決定？哪些不能被隨機覆蓋？
- [ ] **重玩與存檔**：如何避開上一局；重新整理、HMR、重設階段及舊存檔各保留什麼？
- [ ] **場景與模型**：列出動線、停靠位置、真實目標、提示與需要沿用／新增的模型；每套配置是否都看得見、碰得到、走得通？
- [ ] **驗證方式**：如何指定每套配置重現問題；檢查哪些操作順序、重載情況、滑鼠與觸控流程？

關卡完成後，把已實作項目、暫緩項目與幼兒試玩發現同步寫回計畫，讓文件反映實際能力。
