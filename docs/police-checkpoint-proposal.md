五步首版的實測結果保留在[歷史紀錄](history/effect-adoption.md#2026-10-28-警察五步臨檢首版)，不作為六步版本已驗證的證據。

依據：[關卡設計原則](mission-design.md)、[Effect 契約](effect-usage.md)、[驗證指南](effect-verification.md)、[建模清單](model-catalog.md)。

## 六次主要操作

幼兒協助警察設置臨檢、接送查證後的通緝犯，再收運留下的小客車、恢復通行。
同一段直路設有臨檢車位、獨立等候區與前側接送位，車輛沿短路徑自動轉向。

| 次序 | 幼兒操作 | 自動銜接與依賴 |
| --- | --- | --- |
| 1 | 拖巡邏警車進臨檢車位。 | 警車停妥後，兩台重機從畫外沿各自車道駛入待命，第二台晚 0.25 秒；兩車停妥才開放第 2 步。交通錐與臨檢牌預先放妥。 |
| 2 | 拖任一台重機到出口警戒位。 | 另一台留守入口；計程車與載貨平板車各短暫停車、查驗、放行；第三台小客車停妥後，警員從待命點走到車旁才開始查驗，查到通緝資料後陪同下車。 |
| 3 | 拖偵防車進前側接送位。 | 警員與受檢者先走到獨立等候區；偵防車由畫外沿前側車道駛入待命，停妥才讓幼兒拖到接送位，再進入開門階段。 |
| 4 | 橫向拉開面向玩家的側滑門。 | 保留直徑 96 px 抓取區與至少 72 px 手勢，點一下不開門；沿短步行路徑上車，自動關門。 |
| 5 | 拖偵防車朝出口出發。 | 選中重機先自動領行，才交給幼兒拖車；偵防車離場後拖吊車倒車進入。 |
| 6 | 拖平板拖吊車倒車對準小客車。 | 對位後放下原平板與斜板，絞盤掛接並拉車上板、升板固定，再載車離場；其餘警車、重機離場後撤收設施、恢復通車並慶祝。 |

六次指六個主要手動任務，每個可鬆手續拉，不要求一次拖完。沿用到位 0.4 秒停留或有效放手的接手規則，下一階段必須重新抓取。
一般車查驗各 4.4 秒，第三台含下車陪同為 7.2 秒；無新增放行按鈕、人物拖拉、車牌辨識或倒數。
通緝身分以資料比對交代，不以車色或人物衣著作為幼兒判斷線索。

## 進場動畫與交接

依[車輛進出場規則](mission-design.md#車輛進出場與交接)，後續勤務車不直接在畫面內切成可見。
警車就位後接 `bikes-arrival`（2 秒），兩台重機由進場側畫外駛到各自的手動起點；
第三台車查驗及陪同下車結束後接 `van-arrival`（1.8 秒），偵防車沿前側道路駛到手動接送起點。
兩段動畫途中不顯示抓取提示、不接受拖曳，到位後才解鎖原本的任務；仍是六次手動操作。

起點使用與離場相同的完整車身畫外距離，隨畫布寬度調整；路線整套左右鏡射。
固定相機、模型大小、原手動起終點與側門方向不變。進場時間存入既有 `elapsed`，重載與 HMR 接續當時位置。
快照維持版本 3：沒有新增必要欄位或改變既有階段的含義，只有階段集合加入兩種自動進場；完整既有版本 3 的待命／工作狀態仍直接續玩，不重播已完成的進場。版本 1／2 仍拒絕，無遷移分支。

### 警員步行與查驗交接

第三台小客車的 `inspect` 前 1.5 秒為停車，警員保持前兩台車查驗時的待命位置；1.5～2.9 秒繞到近側車旁，2.9 秒到位後才舉手及顯示查驗圖像。3.5 秒顯示查證結果，4 秒開始陪同行走，7.2 秒抵達等候區。原三車時間、六次手動任務與固定鏡頭不變。
警員的查驗站位留在全開車門外，陪同路徑與受檢者錯開；抵達等候區後沿同一位置等待偵防車，上車時從該等候點走到門口，不在切階段時重設座標。沿用原制服人物與可動手臂，以位移、輕微步行起伏和擺臂呈現移動，不新增模型或人物操作。
`officerPose` 為純 domain 計算，位置、起伏及擺臂皆由既有 `elapsed` 恢復；Schema、version 3、生命週期與 E01～E09 不變。共用保存 adapter 包含走向車旁、陪同與上車中的快照，CI 保留查驗提示延後及步行中途 HMR／reload 案例。

## 車輛任務列與模型

四格依序是巡邏警車、雙重機、偵防車、平板拖吊車。兩台重機以雙車圖示表達同組工作；偵防車進場／開門／押送共用同格，開門顯示整車開門姿態，押送完成才勾選。拖吊車載車完全離開後才勾選。
進度條按六項工作量計算；三台受檢民用車不混入勤務車列。

| 使用物件 | 沿用來源與處理 |
| --- | --- |
| 巡邏警車、通緝犯小客車 | [createCar](../src/runtime/car.ts) 原模型，通緝車用可開門小客車，輪廓與偵防廂型車明確分開。 |
| 雙重機、偵防車 | [警察既有模型](../src/missions/police-patrol/vehicles.ts)，不再把一般廂型車變體當作通緝車。 |
| 計程車 | 原轉運站 `createTaxi` 原樣抽到 [taxi.ts](../src/runtime/taxi.ts)，原關保留匯出。 |
| 載貨平板車、兩箱貨物 | 共用 [createFlatbed](../src/runtime/construction-models.ts) 六輪整車與原碼頭 [createPalletCargo](../src/runtime/pallet-cargo.ts)，不縮車；碼頭保留貨物匯出。 |
| 平板拖吊車 | 原交通 `createTowTruck` 原樣抽到 [tow-truck.ts](../src/runtime/tow-truck.ts)，保留平板、斜板、絞盤與固定帶，原關保留匯出。小客車姿態按原平板表面及前後輪接地推導。 |
| 人物、交通錐、路障、街景 | 沿用既有共用入口；場景只安排臨檢標誌、鋪面、短鋼索與掛鉤演出。 |

每次只進場一台受檢車，其他車留在畫外，不用拉遠鏡頭或縮小車體容納隊列。
第一、二台為計程車／載貨平板車，順序隨局改變；第三台固定為通緝小客車。

## 重機二選一提示

原本固定示範一號重機，可能讓幼兒誤以為只能選它。現在兩台停妥後持續標示可選，小手輪流示範；實際選擇仍由孩子直接抓到的車決定。

採用「**兩台同時標示可選，一隻小手輪流示範**」。兩台停妥後，各出現相同樣式的柔和靜態底圈，字幕為「選一台重機，拖到出口」，補充「另一台留守入口」。出口只保留一個共用目的地，標為「出口警戒位」，不隨示範把出口命名為某一號重機。

| 方案 | 判斷與取捨 |
| --- | --- |
| 只有一隻小手輪流示範 | 比固定示範一號更能展示另一個選項，但輪到誰的瞬間仍可能被理解成只能選誰；建議搭配兩台持續可見的可選標記。 |
| 兩台可選底圈＋單一小手輪播 | 本版採用：持續交代選擇範圍，一次教一條實際拖曳路徑；孩子不必等輪到想要的車。 |
| 兩隻小手同時示範／先跳出選車面板 | 前者同時展示兩條動線，可能分散注意；後者增加選車再操作的步驟。本關先保留直接抓車，不採這兩種方案。 |

### 輪播與操作規則

1. 僅在 `guard`、`ready`、尚未選車且 `work.guard=0` 時輪播。兩台仍在進場時不亮可選底圈。
2. 每台完整演示一次「按住 → 沿自身路線拖動 → 停妥 → 小手淡出」，才切另一台；現有直路／轉彎示範完整週期分別約 2.4／3.65 秒，切換須遵守完整週期，不能以統一短間隔截斷二號的轉彎。具體節奏仍待手機與幼兒試玩調整。
3. 一次只顯示當輪的一條教學路線與一隻小手，兩台可選底圈持續保留。輪到二號時沿二號真實路徑示範，不畫穿過車體的直線。示範順序可隨既有左右配置交換，避免每局固定從一號開始；不另抽選或保存示範順序。
4. 抓住任一台立即停止輪播、隱藏小手與另一台的可選底圈，路線與出口提示跟隨實際抓到的車，即使當時正在示範另一台也一樣。沿用原大範圍抓取與兩台重疊時距離優先的命中規則，不加確認按鈕。
5. 有部分行程時鬆手／取消，只從選中車的目前位置示範剩餘路線，另一台保持入口留守角色。零進度點按／取消且 domain 解除選擇時恢復雙車可選，從被碰觸的車完整示範一輪，再繼續交替；不能播完一輪就改寫 `selected`。
6. 減少動態模式顯示兩台相同的靜態底圈及各自短方向箭頭，保留共用出口標記，停止小手移動與輪播。字幕／無障礙標籤清楚說明「兩台任選一台」，聲音不是必要提示。

### 四邊取景補充

保留目前相機、模型大小與兩台的手動路線；新增提示不能靠拉遠鏡頭容納。下表列出提示的必留範圍；實際驗證範圍與限制見本節執行紀錄。

| 邊緣 | 必留與安排 | 桌面／手機需驗證 |
| --- | --- | --- |
| 上 | 原字幕與頂部控制列；沿用現有文字區域，不新增選車面板 | 底圈／小手均不壓到字幕，提示切換不使 HUD 跳動。 |
| 下 | 近側二號重機及其可選底圈、示範小手 | 二號整車與提示不被任務列／手指遮住，底圈不誤標其他物件。 |
| 左 | 左進右出時兩台待命重機的完整可選標記，反向時的共同出口 | 兩台底圈能分辨且不被裁；從任一台抓取皆接上正確路線。 |
| 右 | 右進左出時鏡射後的兩台標記，正向時的共同出口 | 與左側同等可辨識；示範轉彎及出口標記不出框。 |

至少覆核桌面 `1280×800`、直向 `390×844`，並沿用既有 `980×800`、`390×619`、`320×568`、`844×390` 畫布案例；主體投影寬度應維持前表，新增提示的邊界另行量測，不把目前模型取景通過視為新提示已通過。

### 資源、存檔與驗證

沿用 E01～E09：底圈 SVG 由 connection 擁有並隨既有 finalizer 清理，沿用原本的取得與釋放方式。輪播使用現有 frame loop 的局部呈現時鐘，進入可選狀態時起算，hidden 不累加；不新增 `setInterval`、服務、背景 Fiber 或音效依賴。提示目標只由可操作集合及顯示順序推導，不能覆寫 domain 的 `selected`、`active`、`work` 或 `elapsed`。
Schema／version 3、resume、不變量與既有部分重機 fixture 不變；重載／HMR 恢復已選車及部分進度，尚未選車時可重播提示開頭。現有 Effect 任務差異表維持現況。共用 `runtime/drag-hint.ts` 只抽出原有完整週期計算，供警察關卡決定輪播時間；九關既有單一提示行為不變。已核對架構邊界與九關呼叫端，輪播決策留在警察關卡。畫布改變尺寸時從目前示範車重新起算，避免新投影路線被截斷。

驗證案例涵蓋純提示決策、police／development CI 與內建瀏覽器；計畫檢查：兩方向輪播兩車、二號完整轉彎、提示一號時直接拖二號、切換瞬間抓取、零進度取消、部分拖曳取消與 reload／HMR、hidden／回選單、減少動態模式及上述尺寸。驗收重點是「看得出兩台都能選、只需選一台、操作開始後不搶回注意」，幼兒是否理解仍需實際試玩，不由動畫播放成功直接推定。

## Effect 整合清單

六步改版修改 domain、scene、session、UI 與快照，沒有生命週期變更或新服務。共用 runtime 抽出純模型與原有提示週期計算，原呼叫端 API／模型與單一提示行為不變；本次二選一提示沒有再修改快照。

| 契約 | 採用方式 |
| --- | --- |
| E01–E03 | renderer、scene、observer、音效與 connection 仍由現有 scope 擁有；提示及事件以 connection signal 取消；部分取得失敗依獨立 finalizer 回滾。所有新模型幾何與材質歸 scene 清理。 |
| E04 | 保留手勢音效解鎖、靜音及失敗後續玩；查驗與放行都有畫面提示，不依賴聲音。 |
| E05–E06 | 同步 pagehide／最後存檔、記憶體優先、storage 不可用降級不變；新版 Schema 與 resume 核對查驗索引、階段、六項 work、選車及時間。 |
| E07–E08 | 沿用 services、startup 組裝與六階段追蹤、既有 lazy 入口；純 domain 與逐幀計算保持普通 TypeScript。 |
| E09 | 沿用 700 ms autosave 與 frame loop 互相監督；三車查驗、重機／偵防車進場、上車、拖吊與清場皆為 domain 時鐘，不另建 timer，導航／取消／失敗停止工作。 |
