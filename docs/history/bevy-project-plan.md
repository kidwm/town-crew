# Town Crew（小小城市隊）

## 專案定位

一款使用 Rust、Bevy 與 WebAssembly 製作、可在瀏覽器遊玩的幼兒車輛任務遊戲。玩家帶領一支城鎮車輛小隊，依序操作不同車輛完成施工、維護與救援任務，並立即看見環境恢復與交通重新運作。

目標玩家約四歲，因此遊戲以圖像、動畫與聲音引導，不依賴閱讀能力，也不設計倒數、生命值、扣分或失敗畫面。

## 核心體驗

```text
看見需要修復的環境
→ 工程車進場
→ 完成一個直覺操作
→ 環境產生永久變化
→ 下一輛工程車接手
→ 完工後居民與交通恢復活動
```

`Town Crew` 是可擴充的城鎮任務框架；「小小工地隊：修復道路坑洞」是第一個任務。未來可加入消防救援、道路維護、清潔與運輸等任務，但不納入第一版範圍。

## 第一個垂直切片

只製作一個場景、一個坑洞與三輛工程車。

### 施工流程

1. 挖土機清理坑洞中的三塊碎石。
2. 傾卸卡車把填充材料倒入坑洞。
3. 壓路機在路面來回兩次，把填料壓平。
4. 路障移開，一輛小汽車通過並鳴笛，工程車做出慶祝反應。

### 操作設計

- 以 pointer input 為核心，同時支援滑鼠與單指觸控。
- 第一版由工程車依序自動進場，不製作選車畫面。
- 可互動目標使用跳動、發光或移動示範提示。
- 點錯或拖錯不扣分；物件柔和復位後再次提示。
- 操作命中範圍應大於視覺物件，避免要求精細控制。

### 各車輛互動

#### 挖土機

首版優先採用「拖曳挖斗到發亮碎石」的半自動操作：玩家決定目標與拖曳方向，接觸後由動畫完成挖取與卸料。這比完整模擬機械臂更適合幼兒，也比較容易在觸控裝置上成功。

#### 傾卸卡車

卡車停妥後以向上動態提示車斗可操作。單純點擊只會讓車斗輕微抬起並復位；玩家從靠車頭至中央的斗體向上拖曳時，車斗角度會連續跟隨手指，達到門檻後動畫才自動完成升斗、倒料及復位。靠車尾鉸鏈的區域不觸發操作。

#### 壓路機

玩家在道路上水平拖曳壓路機。通過坑洞區域時計入進度；完成兩個方向的通過後，路面轉為平整狀態。

## 美術與攝影機方向

- 低多邊形 3D、玩具般的圓潤比例。
- 固定正交攝影機，形成 2.5D／等角視覺，不讓幼兒控制相機。
- 橫向畫面，主要互動集中在中央安全區域。
- 第一階段的場景與車輛使用 Bevy primitive 與純色材質；少量操作圖示可使用自製向量貼圖，不等待正式模型。
- 顏色明亮但維持清楚對比；危險符號只作工地裝飾，不營造緊張感。

## 技術方向

- Rust + Bevy。
- 桌面原生版本用於快速開發，WASM 版本用於實機驗證。
- 以 WebGL2 可支援的功能作為最低基準；WebGPU 為可選的漸進增強。
- 避免首版依賴 compute shader、進階後處理或大量即時光源。
- 開發初期鎖定明確的 Bevy 版本，避免依賴 `main` 分支 API。
- 物理不作核心依賴；車輛與機械臂優先使用受控動畫、曲線與碰撞區域。

## 開發與驗收方式

- 日常開發優先使用 `cargo run --features bevy/dynamic_linking` 啟動原生版本，以縮短增量編譯與迭代時間；WASM 與 release 建置維持靜態連結。
- 原生驗收包含啟動 log、實際視窗渲染、滑鼠操作與流程狀態確認。
- 每個里程碑完成時必須執行一次 WASM 瀏覽器驗收。
- 涉及 pointer input、畫面尺寸、資產載入、音訊或 Web 平台行為的變更，必須同步驗證 WASM。
- 瀏覽器驗收包含 canvas 建立、console 錯誤、滑鼠／觸控操作及 WebGL2 路徑。
- 原生版本通過不代表瀏覽器版本通過；兩者結果應分別記錄。

## 建議狀態結構

```text
Loading
→ ExcavatorWork
→ DumpTruckWork
→ RollerWork
→ Traffic
→ Complete
```

首版可以直接使用單一 `MissionPhase` resource 或 state。等第二個任務出現後，再抽象成資料驅動的任務系統。

概念資料：

```rust
enum MissionPhase {
    Excavator,
    DumpTruck,
    RoadRoller,
    Traffic,
    Complete,
}

enum VehicleKind {
    Excavator,
    DumpTruck,
    RoadRoller,
}
```

## 建議程式模組

```text
src/
├── main.rs
├── game.rs          # 全域 state、流程與重啟
├── input.rs         # 滑鼠／觸控共用 pointer 行為
├── mission.rs       # 任務流程與共用狀態
├── construction.rs  # 工地、坑洞、道路狀態
├── vehicles/
│   ├── mod.rs
│   ├── excavator.rs
│   ├── dump_truck.rs
│   └── road_roller.rs
├── camera.rs
└── feedback.rs      # 提示、音效、粒子與慶祝
```

這只是初始邊界，不應為了符合目錄而過早拆分很短的檔案。

- [x] M1b：傾卸卡車進場，點擊或上拖車斗後自動卸料並復位。
- [x] M1c：壓路機完成雙向兩趟整平；第一趟降低填料，第二趟完整覆蓋坑洞。

實作備註：

- M1 灰盒流程與挖土機 IK 經過手動驗證後、進入 M2 前進行第一輪模組整理。
- 第一輪只拆分 `vehicles/`，分出挖土機、傾卸卡車與壓路機的生成、互動、動畫及重設邏輯。
- 任務流程、關卡場景與共用回饋暫留 `main.rs`，等邊界更穩定後再拆分。
- 第一輪只搬移既有行為，不同時改寫玩法或建立通用車輛抽象。

### M2：幼兒可理解性（完成）

- [x] 任一時刻只有當前可互動目標呈現明顯提示，階段切換時由下一輛車自然接手注意力。
- [x] 挖斗本體與當前碎石具備無文字提示；提示不改變 two-bone IK 長度、可達範圍或碰撞判定。

- [x] 三階段 hitbox 維持單指容錯；車斗 hitbox 排除靠車尾鉸鏈區域，背景與錯誤操作不推進任務。
- [x] 重新開始改為固定右下角 UI，圖示嵌入執行檔／WASM，mouse 與 touch 由 UI picking 共用 pointer observer。
- [x] 目標年齡幼兒完成無文字完整流程觀察；依實際回饋修正「點擊即倒料、缺乏拉動旋轉感」問題。
- [x] 完成原生、WASM WebGL2、Android 與 iPad 的開場至重新開始完整回歸。

實作與觀察備註：

- 挖土機以挖斗脈動、挖斗至當前碎石的移動光點及單一發亮碎石建立操作關係；拖錯、放開或取消後柔和回到 home 再提示。
- 車斗在 0–60 px 上拖範圍內連續旋轉，跨過門檻才接手倒料；單點只做輕微抬起回彈，不再完成任務。
- 壓路機第一趟顯示主要方向並預告反向第二趟；完成第一趟後只保留反向提示。
- M2 試玩未發現需要新增文字、失敗條件、計分或額外任務內容的證據。

## 垂直切片完成標準

- 從載入到完工可在瀏覽器完整遊玩，不需鍵盤。
- 玩家不閱讀文字也能完成三階段。
- 任意點錯或拖錯都不會卡死流程。
- 每次操作都有即時的視覺或聲音回饋。
- 施工完成後，路面狀態有明顯差異，且小汽車能順利通過。
- 可以重新開始並再次完成。
- WebGL2 路徑可用；支援 WebGPU 的瀏覽器可使用相同玩法。

## 首版明確不做

- 開放世界或大型 Tile／Voxel 地圖。
- 自由駕駛、方向盤、倒車與精確停車。
- 自由旋轉或縮放攝影機。
- 真實車輛物理、液壓或土壤模擬。
- 關卡地圖、選車畫面、收藏圖鑑與存檔。
- 多個城鎮任務。
- 正式美術資產與複雜 Shader。
- 計分、計時、生命值或失敗條件。

## 試玩結論與後續驗證

1. 挖土機的半自動拖曳已能支援第一個垂直切片；是否需要更強的工程車操作感，留待後續持續觀察，不在 M2 增加完整機械模擬。
2. 壓路機的水平自由拖曳與雙向提示已可由目標玩家完成；第一版不改為固定軌道。
3. 目前三階段 hitbox 在滑鼠與單指觸控裝置可用，車斗命中區已依機構語意排除鉸鏈端。
4. 車輛自動依序進場可完成無文字流程，第一版不增加選車畫面。
5. WASM 首次載入時間、資產體積與行動裝置效能仍需在 M3 發佈品質階段量測與控制。

## 後續產品方向（暫存，不納入首版）

- 完整修路：鋪路機、道路畫線車。
- 蓋遊樂場：挖土、運沙、吊裝、澆築。
- 修復小橋：拆除橋板、運料、吊裝與整平。
- 建造消防站：地基、混凝土、吊裝與招牌。
- 打通山洞：鑽孔、清石、運輸與畫線。
- 挖土尋寶：作為較自由的工程車互動模式。
- 消防救援：撲滅小火、移除障礙或幫助受困的小動物。

## 下一步

M2 已完成。先保留目前已驗證的玩法、狀態、hitbox、提示節奏與跨平台流程作為基準，再進入 **M3：表現與發佈品質**。

M3 第一輪先做低風險的距離驅動車輛動態：

1. 傾卸卡車進場時車輪依位移旋轉。
2. 壓路機進場與玩家拖曳時，輪胎及前滾筒依位移旋轉，停止移動即停止。
3. 小汽車通行時車輪依位移旋轉。
4. 動畫不得改變車輛 root transform、pointer hitbox、任務門檻或 M2 提示狀態。
5. 完成原生檢查後，再於 WASM WebGL2、Android 與 iPad 回歸完整流程與效能。

車輪與滾筒動態穩定後，再依序加入基本音效與行動瀏覽器 audio unlock、少量施工回饋、載入畫面、WASM 體積與首次載入量測。M3 不加入正式模型、複雜 shader、大量粒子、攝影機特效、新關卡、計分或失敗條件。
